## Token Optimization Mode (LLM Wiki Layer)
Roles: Hermes = Router + Orchestrator + Context Manager + Final Decider. `Knowledge/indexes/` = wiki layer. Sub-agent = targeted researcher.
Flow: Task → `boom-router` → `PROJECT_MAP.md` route → `libby/find.py` → 1 primary skill → minimal read → execute → validate → STOP.
1. Workflow first: load only the relevant workflow/skill; never bulk-read all workflows, skills, or docs.
2. Wiki layer: `PROJECT_MAP.md` (route table) → `libby/find.py --route <topic>` (≤5 hits, open 1–3) → targeted section/frontmatter only. Never bulk-read `Knowledge/` or `Output/`.
3. Skills: select by name/description; 1 primary, secondary only when truly needed; lazy-load references.
4. Sub-agent only when expected context saved > delegation overhead: large search space, unknown location, cross-source comparison.
5. Sub-agent prompt = question + scope + output format. Return ONLY: Finding (1–3 sentences), Files, Symbol/Section, Evidence, Confidence. No file/page dumps.
6. Depth 1, no nested agents; parallel sub-agents only for independent discovery; no duplicate reading.
7. Search before read: `find.py` first; for code, narrow filename search under `scripts/` (search_files content mode fails on E: — use terminal `grep -ril` or file-glob mode).
8. Minimum sufficient context: read enough → implement early → test. On failure: error → targeted search → minimal read → fix → validate (never restart full exploration).
9. STOP when validated; no "just in case" exploration.
